# 004 — Should the app open by double-clicking index.html?

**Status:** resolved
**Raised:** 2026-11-24

## Context
Opening `index.html` directly (`file://`) shows a blank page. Browsers block ES modules, `fetch()` of module and preset files, and cookies on `file://`. Today the app needs `py -m http.server 8000 --bind 127.0.0.1`.

A notice saying "run the local server" is being added either way.

## Options
- **Keep the server requirement** (current). Simplest, keeps the module/CSV/markdown file layout.
- **Ship a single bundled file** (`studyblock.html`) with all JS, CSS, module data and presets inlined, generated by a small Python script (`py tools/bundle.py`). Double-click works. Progress uses localStorage only (cookies don't work on `file://`).
- **Ship a tiny launcher** (`start.bat`) that starts the server and opens the browser.

## Resolution
The user wants it to run without a server, with a user-chosen data folder for storage. Plan:
- Single bundled file via `py tools/bundle.py` → `dist/studyblock.html`.
- An optional data folder through the File System Access API, prompted on `file://`.
- GitHub Pages compatibility.

See "Running modes" and "Data folder" in CLAUDE.md.
